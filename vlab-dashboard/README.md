# Virtual Labs Student Count Dashboard

React + Vite frontend with a Flask + SQLite API. Everyone can view and filter the dashboard; only a
logged-in admin can add, edit, delete or import records. Data: 116 rows extracted from 50 scanned IIT
Bombay Virtual Labs workshop reports (Feb to Oct 2024, NCID 48).

## Run locally

Install frontend dependencies and build the React UI:

```bash
npm --prefix frontend install
npm --prefix frontend run build
```

Then start Flask:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

Open http://127.0.0.1:5000. The first start creates the SQLite database and fills it from
`data/vlab_student_count_dataset.csv`. Admin credentials are read from `.env` or the process environment.
For local use, copy `.env.example` to `.env` and replace the sample password and secret key with your own
values. The Vite dev server is also available with `npm --prefix frontend run dev` while Flask runs on port
5000; it serves the UI on port 5173 and proxies `/api` requests to Flask.

## Production

Build and run the production container locally (requires Docker):

```bash
docker build -t vlab-dashboard .
docker run --rm -p 8000:8000 --env-file .env -v vlab-data:/data vlab-dashboard
```

Open http://localhost:8000. The container requires `ADMIN_PASSWORD` and `SECRET_KEY` and writes SQLite data
to `/data/vlab.db`.

### Deploy to Render

This repository includes `render.yaml`, which configures a Docker web service, a `/data` persistent disk, and
`/api/records` as its health check. In Render:

1. Create a new Blueprint and connect the Git repository containing this project. If the project is in a
   subdirectory, set the Blueprint's root directory to that folder.
2. Review the service plan and persistent disk before creating the service. The Blueprint uses Render's
   Starter plan because persistent disks are not available on the free web-service plan; Render may charge
   for the service and disk.
3. When prompted, enter a unique, strong `ADMIN_PASSWORD`. Render generates `SECRET_KEY`; the Blueprint sets
   `DATABASE_PATH=/data/vlab.db`, `COOKIE_SECURE=1`, and production mode.
4. Deploy, then verify the public dashboard, `/api/records`, and admin login using the password you configured.

Do not commit `.env` or bake secrets into the image. Keep the disk attached when redeploying and back up its
database regularly. Before connecting a repository, make sure it contains only this project; do not push a
parent/home directory that may contain unrelated personal files.

## API
| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | /api/records | public | all records |
| GET | /api/export.csv | public | CSV download |
| GET | /api/me | public | `{admin: bool}` |
| POST | /api/login, /api/logout | | `{password}` |
| POST | /api/records | admin | add `{date, dept, users, usage}` |
| PUT/DELETE | /api/records/<id> | admin | edit / delete |
| POST | /api/import | admin | multipart CSV upload; skips rows already present |

CSV columns: `date,department,student_count,usage_count,duplicate_report,source_pdf`.
Rows with `duplicate_report=Y` are shown greyed out and excluded from totals.

## Notes
- "Students" are daily user counts summed over report days, not unique students; a student using the labs on
  several days is counted each day. The PDFs don't identify individuals.
- Reset to the original dataset: `flask --app app reset-data`.
- Security: cookie is HttpOnly + SameSite=Lax (blocks cross-site POSTs), inputs are validated server-side, failed
  logins are delayed. For internet use add HTTPS and consider rate limiting at the proxy.
